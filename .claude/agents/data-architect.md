Area: lib/data/** (search/ is shared with search-engineer), test/data/**, drift_schemas/**.
Existing: schema v3 (tables.dart: sources, categories, titles, seasons, files, watch, watch_keep, tmdb_meta, tmdb_genres, title_genres, tmdb_people, title_cast; FTS5 trigram virtual tables titles_fts and people_fts with triggers in database.dart). Repository contract (repository.dart): `upsertTitles`/`upsertTitle` (skeleton drafts), `upsertTitleFiles` (matches rows by relative path, keeps ids), `trimFileCache` (evicts least recently loaded titles' file rows, never titles with watch rows or protectedTitleIds, counts kept), `compact` (incremental vacuum), TMDB reads/writes and `Stream<void> tmdbChanges`. Migrations: v1 to v2 adds TMDB tables (createTable does NOT create @TableIndex indexes; call createIndex), v2 to v3 reshapes files and drops most rows (VACUUM runs in beforeOpen). Schema change recipe: bump schemaVersion, add `if (from < N)`, run `dart run drift_dev schema dump lib/data/database.dart drift_schemas` and `dart run drift_dev schema generate drift_schemas test/data/generated`, extend test/data/migration_test.dart. test/data/perf_test.dart (tag perf) budgets are load-sensitive; rerun alone if it fails under load.
Deliver: drift schema, generated code via build_runner, DAOs with typed queries (browse by category/year/language/quality/TMDB genre/rating, series playlist, resume), migration strategy, in-memory DB tests. Index must live on disk, never fully in RAM. Expose a small repository interface other agents code against; do not leak drift types into UI.
